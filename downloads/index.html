Install

Four commands on Linux

  1. Fetch the tarball The /latest/download/ URL always resolves to the newest published build.
  2. Unpack and install install.sh copies everything into ~/.local/opt/general-bots and adds a launcher plus a desktop entry.
  3. Start General Bots The first run opens the setup wizard: display name, model provider, API key.
  4. Let the wizard provision services Progress is shown per component; the suite then opens with Chat and Drive.
bash — install
# 1. download the newest build BASE=https://github.com/generalbots/generalbots/releases/latest/download curl -fLO "$BASE/generalbots-linux-x86_64.tar.gz" # 2. unpack and install for your user tar -xzf generalbots-linux-x86_64.tar.gz cd generalbots-*-linux-x86_64 ./install.sh # 3. start it general-bots
Integrity

Verify before you run it

Every release publishes a SHA-256 manifest next to the tarball. Check the file you downloaded — no extra tooling, no keys to import.

  • One manifest, both names

    SHA256SUMS-linux lists the stable alias and the versioned tarball, so the same file verifies either download.

  • Skips what you did not download

    --ignore-missing checks the entries that exist on disk and stays quiet about the rest.

bash — verify
BASE=https://github.com/generalbots/generalbots/releases/latest/download curl -fLO "$BASE/SHA256SUMS-linux" sha256sum -c SHA256SUMS-linux --ignore-missing # generalbots-linux-x86_64.tar.gz: OK
Requirements

What the desktop needs

The download is small because it carries no service archives. The first run fetches the stack, which is where the disk space goes.

System requirements for the General Bots desktop build
Operating system Linux x86_64 — Ubuntu 22.04+ or an equivalent with GTK / WebKitGTK 4.1 — or Windows 10 / 11 x64
Desktop library libwebkit2gtk-4.1-0 is the only required library on Linux
Disk About 4 GB free for the provisioned service stack
Network Internet access on first run to fetch services — or an installers/ bundle for offline use
Privileges None. The installer and the stack stay inside your home directory
GPU Optional. Local model inference runs on CPU without one
After install

Where everything lives

Nothing is installed system-wide and nothing phones home. The paths below are the whole footprint.

Services

PostgreSQL, Valkey, MinIO, Qdrant, Vault, Zitadel and llama.cpp, provisioned by the wizard.

Runtime state

~/.local/share/generalbots holds the stack, workspace and logs. Override with BOTSERVER_STACK_PATH.

Logs

wizard-provision.log and botserver-sidecar.log under ~/.local/share/generalbots/logs.

Offline install

Drop the component archives into installers/ next to start.sh and nothing is downloaded.

Versioning

Stable or pinned

Use the stable URL for the current build. Pin a tag when you need a reproducible install or an older release.

bash — pinned release
# stable: newest published build BASE=https://github.com/generalbots/generalbots/releases/latest/download curl -fLO "$BASE/generalbots-linux-x86_64.tar.gz" # pinned: one tag (the tag-free alias is not published here) TAG=v6.7.0 BASE=https://github.com/generalbots/generalbots/releases/download/$TAG curl -fLO "$BASE/generalbots-$TAG-linux-x86_64.tar.gz"

Versioned assets embed the tag in the filename. The tag-free name exists only on the /latest/ path, so replace v6.7.0 with a tag that has actually been published.

Questions

Before you install

Do I need root?

No. install.sh writes to ~/.local/opt/general-bots, links a launcher into ~/.local/bin and registers a desktop entry. Pass a different prefix as the first argument if you want another location.

Where does my data live?

Everything runtime-related stays in ~/.local/share/generalbots: the service stack, the workspace and the logs. Point BOTSERVER_STACK_PATH at another directory to run an isolated stack.

Can I install without internet access?

Yes. Put the component archives in an installers/ directory next to start.sh before the first run — when that directory has files, the wizard downloads nothing.

Which services get installed?

PostgreSQL, Valkey, MinIO, Qdrant, Vault, Zitadel and llama.cpp. Progress is reported per component and the full log is written to ~/.local/share/generalbots/logs.

Why does a download link return 404?

The link always points at the newest release. If that release carries no desktop assets, nothing resolves. Pin a published tag or build from source.

Is there a macOS build?

Not yet published. Build from source, or run the same software as a managed instance instead.

How do I upgrade?

Download the newer tarball and run its installer again. The runtime state in ~/.local/share/generalbots survives reinstalls.

Rather not run it yourself?

The desktop build and the hosted deployment run the same software. Pick a hosting partner or self-host the server edition.
